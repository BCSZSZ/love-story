# 04｜人数估算、统一评分与扩展接口

版本：`independent-fields-v2` · 配置：`config-bundle-demo-2.0.0`。

## 1. 模型定位

本模型只服务功能演示，不是人口统计研究或社交图谱。学历、收入、年龄、婚姻、国籍、资产等现实中可能相关，当前仍采用独立系数；页面和导出必须写明“演示配置，非真实人口统计”。每个 active 问题必须有具体分布，不能因字段多而返回固定 `p=1`。

固定演示基数 `B = 8,000,000,000`，成年人比例 `a = 0.70`。开场显示 `B`；开始后成年人基数为 `B × a`，成年人系数只应用一次。

## 2. 城市、条件与两个结果

设所选城市质量为 `c`。它来自真实城市配置，只应用一次，不再通过旧 `residence` 字段筛选：

```text
cityAdultBase = B × a × c
```

某个已设置条件的原始覆盖率为 `p_i`，排除强度为 `s_i`，有效覆盖率是：

```text
e_i = 1 - s_i × (1 - p_i)
```

这意味着：

- `s=1`：完整执行原条件，`e=p`。
- `s=0.8/0.6/0.4`：按对应比例放松排除，不改变原年龄区间、金额门槛或类别集合。
- `s=0`：条件不排除任何人，`e=1`。

全部有效条件的覆盖率及同城条件池：

```text
conditionCoverage = ∏ e_i
cityCandidatePool = cityAdultBase × conditionCoverage
```

可触达圈层先由基础档位 `R` 和所有已开助力增幅 `b_j` 计算，并以同城成年人规模封顶：

```text
effectiveReach = min(cityAdultBase, R × (1 + Σ b_j))
reachableCandidateCount = effectiveReach × conditionCoverage
```

助力之间是相对基础圈层的加法，不做复利相乘。两个结果共享 `conditionCoverage`；“圈层内可达”不是把同城条件池再乘一次圈层人数。

种子配置：日常圈 2,000、拓展圈 5,000、城市圈 10,000；朋友 +0.50、家庭 +0.25、相亲服务 +1.00。

## 3. 原始条件覆盖率 `p`

### 3.1 互斥枚举

选中的叶子选项先展开、去重，再求和：

```text
p(any accepted values) = Σ mass[x]
```

预设和单个选项重叠时只计一次。例如“211及以上”与“985”同时出现不会重复累计 985。

### 3.2 数值区间

`bucket_uniform_discrete` 桶为 `[from,toExclusive)`，桶内离散取值等概率。`gte`、`lte`、`between` 根据支持范围、step 和包含端点的语义计算落入比例。金额先按配置汇率规范化为人民币整数元，并保留原币种、原值和 `fxVersion`。

无要求永远是 1，不因 UI 支持边界再次筛选。范围无交集产生输入 issue；不得静默截断。

### 3.3 独立标签

爱好等标签可重叠，使用显式的独立标签演示假设：

```text
p(any_of A) = 1 - ∏(1 - prevalence[x])
```

### 3.4 相对要求

相对要求先使用自身答案解析成普通区间或门槛，再计算 `p`。缺失依赖、类型不匹配或范围无效时返回可定位 issue，并把结果标为 `partial`；不能用 0 代替缺失值。

## 4. 稳定计算与 trace

按配置中的稳定字段顺序全量重算，不依赖点击顺序，也不在旧人数上增量扣减。内部以 log10 累加，避免大量小概率直接连乘下溢：

```text
log10(cityCandidatePool)
  = log10(B) + log10(a) + log10(c) + Σ log10(e_i)
```

trace 对成年人、城市和每个有效条件记录 `rawCoefficient`、`strictness`、`effectiveCoefficient`、`before` 与 `after`。数学零与浮点下溢分开表达；正的极小值不误报为精确零，JSON 不输出 `NaN` 或 `Infinity`。

## 5. 五档放松与建议

默认五档固定顺序为 1、0.8、0.6、0.4、0。结果页每个已设置条件可任意选择一档：

- 行内预览以已应用草稿为基线，只替换这一行的强度。
- 合并预览使用当前所有未应用调整。
- “影响最大的三项”分别只把一个条件移动到相邻下一档，并按同城人数的对数增量排序。
- 点击预览或建议不写记录；点击应用后才更新草稿并触发自动保存。

放松始终满足单调性：若唯一变化是某项 `s` 降低，则同城条件池和圈层内可达都不能减少。

## 6. 统一评分

同一个 `g_i(value) ∈ [0,100]` 同时用于自身和对方要求；字段权重 `w_i > 0`：

```text
Score = Σ(w_i × g_i) / Σw_i
```

自身只对已回答且可评分的问题计分。对象要求先解析具体允许集合或数值范围，再取该集合中的最低可接受分数；这是当前明确语义，不代表匹配概率。

强度 1、0.8、0.6、0.4 都保留原具体要求，因此要求分不变；强度 0 等价“无要求”，该项从要求分中移除。评分绝不乘入人口结果。无可评分项返回 `null`，不是 0。

## 7. 配置和复算

共享 `RuntimeEngine` 只依赖完整 `RuntimeConfigBundle`，不依赖 DOM 或 AWS。浏览器即时计算，服务端根据快照声明的 `configBundleVersion` 和 `configChecksum` 加载同一配置后重新验证、复算并保存；客户端提交的人数和分数不被信任。

新测试使用当前激活配置；已开始草稿固定其版本。版本不存在、checksum 不一致或输入不符合该版本时拒绝云端保存。配置正文规范化后计算 SHA-256，用于浏览器、服务端和 Excel round-trip 一致性检查。

## 8. 扩展接口

`PopulationEstimator`、`ConfiguredUnifiedScoreModel` 和 `RelaxationGenerator` 是对 `RuntimeEngine` 的兼容封装。`AcceptanceEstimator` 继续只返回 `{ status: "not_implemented" }`。未来双向接受度必须作为独立模型版本设计，不得用双方分数差或圈层人数替代。
